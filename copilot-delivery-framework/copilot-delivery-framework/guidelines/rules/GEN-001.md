## Rationale
Every extra abstraction is code that must be reviewed, tested and maintained in a safety-relevant product. Over-engineering raises defect risk and review time.

## Bad
```
Adding a generic IProcessor<T> hierarchy for one call site.
```

## Good
```
A private method or a concrete class used at the one call site; generalise when a second real use appears.
```

## Notes
Reviewer test: could the same behaviour be delivered with fewer types/files/parameters without breaking an existing rule?
